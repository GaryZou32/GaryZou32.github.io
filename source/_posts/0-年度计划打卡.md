# ✅ 2026 训练与作品集 Checklist（最终一页版 · 朴实）

## 0) 今年的真实目标

* [ ] 我在训练“掌控感”：**能解释、能定位、能改对、能量化证明**
* [ ] “做出一个真的能用的助手系统”只是**期末考试题**，主线（A/C/E）可以随时调整
* [ ] A / C / E 的核心价值是：沉淀 **作品集 + 可复用模块库**

---

## 1) 祛魅（只做一次，2–4 周搞定）

目的：以后别人问你“为什么慢了/为什么幻觉/为什么爆显存”，你不会只能说“可能是模型不行”。

* [ ] 手写一个最小 Transformer Block（只用 PyTorch 张量操作）：QKV、mask、softmax、残差、layernorm
* [ ] 手写一个最小训练循环：forward/backward、gradient accumulation、lr scheduler、保存/恢复 checkpoint
* [ ] 写一个最小 tokenizer（不追求工业级）：至少搞清文本→token、特殊符号、padding/stop
* [ ] 写 1–2 页短文：我从手搓里学到了什么（重点：显存、mask、KV cache/为何需要缓存、prefill vs decode）

> 规则：这部分训练可以“禁用高层库”；但你做作品集时不必禁用，别把自己困死。

---

## 2) A：助手应用（能查资料、能用工具、能给结果）

目的：不是“能聊天”，而是**能办事**。

* [ ] RAG 基本链路：资料进来（清洗/切块/入库）→ 能检索 → 能基于检索回答（能说清来源/引用片段或至少列出处）
* [ ] 工具至少 5 个（哪怕是内部工具）：读文件/检索/算分/查表/生成报告等
* [ ] 每个工具都有：超时、失败处理、错误信息、结构化日志
* [ ] 有“退路”：检索空、工具失败、模型超时，都有 fallback（能继续完成任务或给出可解释的部分结果）
* [ ] 可追踪：每次请求有 request_id；能还原完整过程（检索了什么、调用了哪些工具、哪一步慢/哪一步错）

---

## 3) C：模型后厨（在 DGX 上跑得快、稳、省）

目的：你不仅能跑推理，还能**解释性能变化的原因**。

* [ ] 推理服务跑通（vLLM 或等价），A 层能调用
* [ ] 固定 benchmark（脚本/命令都行），每次记录 4 个数：

  * [ ] P50 延迟
  * [ ] P95 延迟
  * [ ] 吞吐（tokens/s 或 QPS）
  * [ ] 失败率（超时/错误）
* [ ] 至少做 2 次“有数据证明”的优化：

  * [ ] 优化#1：P95 或吞吐提升 ≥ 30%（写前后对比）
  * [ ] 优化#2：显存/成本下降（写前后对比）
* [ ] 高并发基本不崩：限流/排队 + 超时 + 重试 + 降级（最简版也行）
* [ ] 我能写出一段解释：为什么某次慢了 30%（例如：上下文变长、并发、缓存命中、batch、prefill/decode 比例、显存压力等）

---

## 4) E：自动考试系统（评估闭环 / 回归测试）

目的：你每次改 prompt/检索/流程，都能**量化**地知道有没有变好。

* [ ] 回归集（regression_set）：全年累计 ≥ 80 条真实失败/边界样本
* [ ] 一键评估脚本：每次重要改动后能跑出对比报告（baseline vs new）
* [ ] 至少输出这些指标（简单就行）：

  * [ ] 成功率（任务是否完成）
  * [ ] 工具调用正确率（该用时用没用、用对没）
  * [ ] 延迟/成本（至少 1 项）
* [ ] 每季度 1 次失败分析（10 条就够）：现象→根因→修复→防复发（加入回归集/测试）

---

## 5) 数据工程（今年的壁垒训练）

目的：你不靠“换大模型”解决问题，而靠**把数据搞对**。

* [ ] 我有一套数据管线脚本：收集→清洗→去重→质量过滤→切分→版本号（可复现）
* [ ] 我至少做过两种过滤：

  * [ ] 规则过滤（乱码/长度/重复/格式不统一）
  * [ ] 质量过滤（打分或 judge 任一，但要可复现）
* [ ] 我做过一次数据配比实验：同任务不同数据比例，比较指标变化（写结论）

---

## 6) 训练动力学（看懂 loss 曲线背后的“鬼故事”）

目的：你能诊断训练/微调问题，而不是玄学。

* [ ] 我会记录训练过程的关键曲线：loss、lr、grad norm、吞吐、显存
* [ ] 我至少写过 2 次训练复盘（每次 10 行也行）：

  * [ ] loss 不降/震荡、或突然爆炸/消失
  * [ ] loss 降了但指标烂（过拟合/数据问题/格式问题）
  * [ ] 灾难性遗忘（tuned 好了但通用掉了）
* [ ] 我做过一次 LoRA/QLoRA 的 rank 或关键超参扫描，并写出“为什么这样选”的理由

---

## 7) Prompt & Skills 资产库（长期积累，变作品）

目的：把“经验”变成你自己的工具箱，而不是散落在聊天记录里。

* [ ] 建 `prompts/skills` 目录（或单独仓库）
* [ ] 每个 Skill 一张卡：适用场景/输入输出/例子/失败模式/处理方式/对应回归样本
* [ ] Prompt 有版本号 + 变更说明；改完必须跑回归集（至少抽测 10 条）
* [ ] 年度数量目标（不求多求稳）：

  * [ ] Skills ≥ 30 个
  * [ ] Prompts ≥ 50 个（含 ≥ 10 个“失败处理/格式强约束”模板）

---

## 8) 刷题（120 题，工程向）

目的：写代码更稳、边界更清楚、复杂度不瞎。

**总量：120 题**（每周 2–3 题）

* [ ] 基础 50：数组/字符串10 + 哈希10 + 栈队列10 + 堆topK10 + 链表10
* [ ] 高频模式 40：二分10 + 滑窗10 + 前缀和/区间10 + 贪心10
* [ ] 图 20：BFS/DFS10 + 最短路/拓扑5 + 并查集5
* [ ] DP 10：一维5 + 序列/背包入门5

**每题必须交付**

* [ ] 时间/空间复杂度
* [ ] 3 个测试用例（边界/典型/反例）
* [ ] 5 行复盘：题型→关键点→容易错→下次秒选方法→工程里对应场景（例如 LRU=缓存）

---

## 9) 每周论文阅读 + 写作（保持新鲜）

目的：跟进方向，但不变成“只读不落地”。

* [ ] 每周读论文 ≥ 1 篇（全年 ≥ 50）
* [ ] 每篇 200–400 字小总结（问题/方法/结果/局限/我能用在哪）
* [ ] 每月写 1 篇文章（可短，但要归档/发布）
* [ ] **每月必须落地 1 个点到系统/模块**（指标、过滤规则、缓存策略、失败分类、评估方法等）

---

## 10) 日志与汇报（训练可持续的“健身计划”）

### 每天（10–20 分钟）

* [ ] 5 行日志：投入时间｜可验证产出｜一个可迁移点｜明日最小任务｜卡点

### 每周（30–60 分钟）

* [ ] 刷题 2–3 题（含复盘卡）
* [ ] 主线项目做 1 个“质量改动”（测试/日志/回归样本/benchmark 任一）
* [ ] 回归集新增 ≥ 1 条

### 每季度（向我汇报一次）

* [ ] 一个最满意的 demo/指标截图（至少 2 个数字：P95/吞吐/成功率等）
* [ ] 3 个失败案例（现象→根因→修复→预防）
* [ ] 10 分钟系统设计口述（我会追问：为什么慢、为什么幻觉、为什么这么设计）
